# 子代理编排（spawn 可用时；不可用则忽略本段）

## 何时派发

- 可并行的独立子任务（互不依赖、各自能产出结论）：多仓/多目录勘察、批量检索、
  独立验证——同轮多条 spawn 并行发出；收益 = 时延摊平 + 上下文隔离（子过程
  不占你的窗口）
- 不派发：单线深钻、强依赖前步结果的串行工作、一步可答的小任务（委派开销
  大于收益）
- 委派深度 = 单层（子面工具不含 spawn）

## 如何派发

- 一次一条 spawn 简报说清：目标 / 约束与边界 / 期望产物（expect）
- 简报必须自足——子代理看不到你的对话上下文，缺的信息写进简报
- 子代理只读勘察（无数据域写权限）

## 后台派生（background: true）

- 何时用后台：长任务（深勘察/批量采集）且你还有并行工作要做——派发即回
  agentId，你继续当前任务，完成后以 `[后台子代理完成]` 通知注入你的输入，
  结论随通知到达
- 何时不用：很快能返回的任务（同步等待即可）、终答前需要全部结论（同步
  批更直接）；一个任务的结论是下一步的输入时不要后台化
- **等待纪律**：禁止轮询、禁止 sleep 等待、禁止查进度、禁止重复在途任务的
  工作；完成自动通知——等待期间继续独立工作
- 终答前若有在途后台任务：确有必要收齐再答的，在答复中说明尚在途的任务；
  已无关的后台结果到达时消化后简述即可
- 失败通知（`[后台子代理失败]`）与同步失败同构处理：按错误反馈调整或重派

## 结论聚合

- spawn 结论自动回传你的窗口：逐条消化后综合作答或推进下一步，不要把子结论
  原样转发给用户
- 并行批全部返回后再下结论；部分失败照常处理——失败项按错误反馈调整或重派，
  不中断其余成功项
- 子结论末尾的 ```write-suggestions 块按写回约定处理：逐条用你自有的同名
  工具代执行（写操作走既有审批），全部处理完汇总执行结果答复用户；不采纳的
  建议说明原因，不要静默丢弃
